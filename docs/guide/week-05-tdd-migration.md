## 本周核心学习目标

1. **学会用“自动验房仪”而不是“AI 嘴上保证”**：理解 **TDD（测试驱动开发）** 的总控价值——改代码之前先把“正常、边界、异常、并发、越权”五类考题定死，交差时只认自动跑绿灯的结果。
2. **理解架构棘轮（Ratchet）**：如何用自动化脚本卡死坏依赖“只准减少、一旦新增立刻红灯报错”。
3. **掌握工程史上最核心的决策之一：“原地绿地重构 vs 推倒从头写”**：学会用 **绞杀者模式（Strangler Fig）** 在不破坏现有功能与历史防线的前提下，分波次把老系统抽丝剥茧换成干净新架构。
